Projects — three layouts to choose between

The shipping page had one bug and one omission. The bug: a project wore a single agent’s mark and reported every agent’s tokens under it, so a project both Claude and Codex worked in read as though Codex never ran. The omission: 98% of every project’s tokens on this machine are cache reads — 187M of 189.5M — and a bare “189.5M” hides the one figure that explains the bill.

Detail is the one that shipped. The other two stay here so the decision can be re-checked against the real thing rather than a memory of it — the same reason the four unused themes are still on the page. They differ in what they spend the panel’s height on. Switch between them above, and switch the sample to Mixed agents to see each hold three agents in one project — today’s real day only has one project with two.

1 · Ledger

The table, detail folded underneath

Six projects on straight columns, a click opens one. The disclosure names each agent, its models, its share, and prints the token mix.

Costs: the detail is behind a click, and this panel shuts when the pointer leaves it — a missed target costs you the panel. Keeps: the most projects on screen, and the smallest change to what already ships.

2 · Split

Nothing behind a click

Each project is a name, a cost, a rail split by agent, and a line that says it in words: claude 99% · codex 1%, then tokens, messages and the cache share.

Costs: four projects instead of six, and no per-model breakdown anywhere. Keeps: the answer is on screen the moment the page opens, which is the only interaction this panel is reliably good at.

3 · Detail — chosen

List ranks, pane explains

Projects down the left, one project in full on the right: cost, a bar per agent, every model that agent used, and the mix with its figures.

Costs: only one project is explained at a time, and it needs a selection to mean anything. Keeps: the panel is a wide, short surface — Settings already splits it in two for the same reason — and this is the only layout with room to name models.

What changed

Settings is the gear's own destination, alongside Overview and Projects. Every control on it is wired: change one and the strip above redraws, which is the only honest way to tell whether a setting earns its row.

Where

In the notch, not a window

The app is an accessory: no Dock icon, no app menu. A settings window would be a second surface to manage for a page of toggles.

It also breaks the loop that matters — the setting you change most is which agents sit in the strip, and you want to change that while looking at the strip, not behind a window covering it.

Shape

Two columns, nothing scrolls

Six groups in one column ran to about 600 points — half the screen height, hanging off the notch.

The panel is a wide, short surface, so the settings follow its shape instead of fighting it. Everything is on screen at once; there is no scroll and no second page.

Colour

Controls get the theme's own hue

Switches and selected segments needed an accent, and the rule says saturated colour belongs to a vendor — a blue switch would have read as an agent.

So each theme's control colour is its own neutral pushed to full: Ink blue, Sable brass, Vapor violet. The rule holds and the themes separate further.
